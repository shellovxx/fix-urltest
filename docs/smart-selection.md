# Умный выбор сервера и REALITY

В настройках секции Connection включите **«Умный выбор сервера»**. Режим применяется ко всем её локальным и импортированным URLTest-группам. Теги групп сохраняются, поэтому ссылки на них в правилах продолжают работать. По умолчанию режим выключен, предел приемлемой задержки — 300 мс.

Forkop преобразует эти группы в `selector` и управляет ими своим контроллером. Нативный URLTest используется только для измерения задержки. Узел становится проверенным после HTTPS GET с ответом 204 от Google и полной загрузки 32768 байт с Cloudflare с ответом 200. Проверки идут через установленный работающий sing-box и конкретный узел; выбор пользовательского сервера при проверке не меняется.

Проверочный SOCKS-вход доступен только на `127.0.0.1`, требует пароль и имеет отдельную учётную запись для каждого узла. Его порт выбирается начиная с 4536, с пропуском портов других настроенных входов. Неизвестная учётная запись не получает маршрут напрямую. Контроллер читает адрес и пароль из конфигурации ядра; Clash API может слушать как localhost, так и LAN-адрес роутера.

## Правила выбора

- При первом запуске выбирается самый быстрый из прошедших проверку узлов. Начальный проход может уточнять выбор по мере поступления результатов.
- Активный узел проверяется каждые 15 секунд, остальные — каждые 3 минуты. Одновременно выполняются максимум две проверки, активный узел получает приоритет. Если все проверки длительные, очередь может задержать следующий запуск.
- Исправный активный узел удерживается, пока медиана последних трёх коротких измерений не превышает установленный предел.
- Один сбой не вызывает переключения. После двух последовательных сбоев резервный узел повторно проверяется перед переключением; отказавший исключается из кандидатов минимум на 60 секунд.
- После трёх циклов с медианой выше предела смена ради скорости разрешается только при выигрыше не менее 50 мс **и** 20%.
- Смена ради скорости сохраняет существующие соединения. При отказе закрываются только соединения, в цепочке которых одновременно присутствуют отказавший узел и управляемая группа. Приложения должны переподключиться; установленное TCP-соединение нельзя перенести на другой сервер.
- При отсутствии проверенных кандидатов группа показывает недоступность и продолжает проверки. Прямого резервного маршрута нет.

Задержка отображается отдельно от состояния передачи данных. Положительные 100 мс могут соседствовать с «Не прошёл проверку»: это означает, что короткий тест прошёл, а полный файл не загрузился. В подробностях группы видны состояние, причина и время проверки каждого узла.

Результаты и карантин хранятся в `/var/run/forkop/health-state.json`, пароль — в закрытом файле `/var/run/forkop/health-password`. Состояние сохраняется при перезапуске сервиса и обновлении подписки. Изменение параметров узла или его цепочки detour сбрасывает результаты. После перезагрузки самого роутера оперативное состояние теряется и узлы проверяются заново. Снимки селекторов при перезапуске не вмешиваются в выбор управляемых групп.

Проверяется HTTPS/TCP. Работоспособность голосового UDP и игр этим тестом не подтверждается. Недоступность контрольных HTTPS-адресов через прокси тоже считается отказом.

## REALITY и обновления ядра

Готовое [sing-box-extended](https://github.com/shtorm-7/sing-box-extended/releases/tag/v1.14.1-extended-2.7.2) поддерживает `tls.reality.support_x25519mlkem768`. Перед генерацией Forkop проверяет поддержку поля командой проверки конфигурации установленного ядра. Если поддержка есть, значение по умолчанию — `true`; явно заданное `false` сохраняется. Для обычного sing-box расширенное поле удаляется из рабочей конфигурации, а интерфейс показывает ограничение совместимости, если в секции есть REALITY-узлы.

Параметр сохраняется при импорте JSON и Clash, а также при импорте и экспорте ссылок. Формат ссылки: `support-x25519mlkem768=1` или `0`; при импорте также принимается `support_x25519mlkem768`. В Clash он располагается в `reality-opts` с тем же именем через дефис или подчёркивание.

Успешное рукопожатие REALITY само по себе не делает узел рабочим: к нему применяются обе проверки передачи данных. Собственное ядро собирать не требуется. При нехватке постоянного хранилища существует поддерживаемый Forkop вариант `extended-compressed`, но распаковка такого ядра требует дополнительной оперативной памяти. На Redmi AX6 параллельная проверка конфигурации с работающим сжатым ядром вызвала OOM, поэтому установлена обычная готовая сборка extended. После сохранения старого ядра вне роутера она помещается; осталось около 6 МБ хранилища и примерно 130 МБ доступной памяти. Перед обновлением ядра учитывайте место для резервной копии и нового пакета.

Результат проверки поддержки ML-KEM запоминается для конкретного установленного бинарника до изменения его размера, времени изменения или inode. Временные проверки конфигурации используют ограничение Go heap `GOMEMLIMIT=32MiB` и более частую сборку мусора; эти параметры не ограничивают работающий сервис.

Ядро можно обновлять через существующий раздел обновлений Forkop. Эти изменения Forkop находятся в отдельной ветке `shellovxx/upstream-fix`; до включения их в upstream обновление самого Forkop может заменить локальные доработки. Перед таким обновлением перенесите изменения этой ветки в новую версию и повторите проверки.

## Проверки разработки

`tests/health_selection.sh` проверяет пороги, карантин, восстановление, отсутствие кандидатов, неполный ответ, HTTP/TLS/тайм-ауты, маршрутизацию отдельных проб и сохранение результатов при обновлении подписки. `tests/health_runtime.sh` запускает настоящий контроллер с подменёнными ответами транспорта: проверяет удержание после одного сбоя, повторную проверку резерва и адресное закрытие соединений после двух сбоев. `tests/reality_mlkem.sh` проверяет импорт и экспорт параметра, включая явное `false`.

Для внедрения сохраните конфигурацию и текущее ядро вне роутера, проверьте память и место, проверьте конфигурацию новым ядром, установите изменения, обновите подписку, перезапустите сервис и наблюдайте не менее 30 минут. При сравнении ядер не запускайте два экземпляра на роутере с недостаточным запасом памяти.
